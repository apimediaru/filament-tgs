# ADR-026: восстановление черновика создания

**Status:** active
**Created:** 2026-11-19

## Контекст

Страница создания ТГС сохраняет блоки за провизорной записью. При открытии того же черновика
введённые значения обычных полей пропадают, даже если браузер уже отправил их на сервер.
Сохранение этих значений как атрибутов модели может преждевременно подтвердить запись.
Отдельное хранилище в БД потребовало бы своей схемы и правил очистки.

## Решение

Страницы с `HandlesProvisionalCreate` восстанавливают блоки и обычные поля при возврате
к тому же черновику в той же сессии. Доступ проверяется через серверную сессию. Значения
полей лежат в кэше Laravel отдельно для каждого сочетания сессии, токена и провизорной
записи. Это позволяет сохранять два черновика одновременно без перезаписи снимков
при сохранении общего объекта сессии. Сохраняются и незавершённые значения.
Текст отправляется после короткой паузы при вводе, списки и переключатели — при изменении.
При повторном открытии восстанавливается последнее успешно сохранённое значение.

Восстановление обычных полей охватывает текст, даты и выбранные значения. Временные файлы
из обычных полей формы загружаются заново. Медиа, уже сохранённое внутри блока ТГС,
восстанавливается вместе с блоком.

Ошибки создания оставляют черновик доступным для продолжения. После успешного создания
запись становится видна по обычным правилам сайта, а снимок полей черновика удаляется.
«Создать ещё» открывает отдельный пустой черновик.

## Последствия

Восстановление доступно, пока действует сессия и существует её провизорная запись.
У разных черновиков свои значения даже при параллельной работе в нескольких вкладках.
Один адрес из чужой сессии не даёт доступа к полям или блокам. Пакет задаёт общий порядок
восстановления, а поддерживаемые поля определяются схемой конкретной формы.
