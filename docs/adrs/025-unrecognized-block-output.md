# ADR-025: контракт нераспознанного блока

**Status:** active
**Created:** 2026-11-19

## Контекст

ТГС отдаёт нераспознанный блок с исходным `type` и данными из хранилища. Сюда попадают
и блоки отсутствующего типа, и блоки известного типа с несовместимыми данными. В релизе
`v0.1.4` JSON допускает объект и список в `data`, а сгенерированное объявление описывает
только объект. Исходный `type` может совпасть с ключом известного блока.

## Решение

Сохраняем форму JSON и исходный `type`. `UnknownBlock.data` описываем как
`Record<string, unknown> | unknown[]`. Из существующего реестра генерируем `KnownBlock`.
Полный тип `Block` включает `KnownBlock` и `UnknownBlock`.

## Последствия

Сайты могут читать ранее сохранённые блоки по прежнему ключу и с прежней формой данных.
Чтобы обратиться к полю известного блока в полном `Block`, потребитель проверяет и `type`,
и наличие ожидаемого поля. Отдельный ключ для нераспознанных блоков позволил бы обойтись
одной проверкой, но потребовал бы поменять JSON и обновить его потребителей. Приведение всех
`data` к объектам изменило бы форму уже существующих списков.
